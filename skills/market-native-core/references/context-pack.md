# Context pack

A context pack is the only thing the writing model reads before writing. It is generated by
`scripts/build_context.py` from the library and written to `packs/<pack_id>.md` (for the
model) and `packs/<pack_id>.json` (for `validate_copy.py`).

The pack exists because "read the library" does not work. A model told to read a folder will
read too much, miss the one objection that mattered, or quietly fall back on what it already
believed. A pack built by code from fixed selectors removes that choice.

## Selectors

| Selector       | Required | Effect                                                             |
|----------------|----------|--------------------------------------------------------------------|
| `--locale`     | yes      | Picks `markets/<locale>/`, jurisdiction, CTA default, language list |
| `--channel`    | yes      | Picks `channels/<channel>/limits.json`, filters claim eligibility  |
| `--page`       | yes      | Names the blueprint the adapter should use; filters limits         |
| `--audience`   | yes      | Filters claims and objections                                      |
| `--product-id` | no       | Filters claims, glossary and objections tagged for the product     |
| `--concepts`   | no       | Comma list of tags; narrows terms, claims and objections           |
| `--intent`     | no       | Free text stored in the pack for the writer (e.g. "compare vs X") |

## Contents, in order

1. **Identity block.** `pack_id`, generated date, every selector, jurisdiction, default CTA,
   primary-language flag for the market.
2. **Company in one line** and the differentiation section of `core/brand.md`.
3. **Product** entry if a product id was given.
4. **Eligible claims.** Only `verified`, unexpired, eligible for this locale and channel,
   matching product and audience. Each with id, statement, evidence summary, expiry. The
   number of claims excluded and why (expired, wrong channel, wrong market) is reported so the
   writer knows the pack is thin because of the rules, not because the company has nothing.
5. **Required terms.** Approved glossary entries, narrowed by concepts or product when given.
   Each with term, `search_term`, usage example.
6. **Blocked terms.** Technical or regulatory terms still `pending_review`. The writer must not
   use them and must not substitute an invented alternative; it should say the term is awaiting
   approval.
7. **Forbidden terms.** `banned.txt`, every `alternatives_to_avoid`, every `rejected` glossary
   term, and the generic cliché list for the language.
8. **Objections** for this audience, with buyer words and the claim that answers each.
9. **Voice** (`markets/<locale>/voice.md`, whole file; it is short by design).
10. **Limits** for this channel and locale, per field.
11. **Competitor summary.** Count, date range, the `gaps` lines, and the most common section
    order. Not the full entries; the writer needs the pattern, not the pages.
12. **Freshness warnings.** Stale competitor data, claims expiring within 30 days, missing files.

## Size

A pack for one page in one locale should be one to two pages of text. If it is longer, the
selectors are too loose or the library is storing raw material where it should store
summaries. `build_context.py` prints an approximate token count.

## Guarantees the adapter can rely on

- Every claim in the pack may be stated in this locale on this channel.
- Every required term is human-approved.
- Every forbidden term will fail validation if it appears.
- The limits match the layout the copy will be pasted into.
- If something needed is missing, the pack says so in the warnings section instead of leaving
  the writer to guess.
